# 02-http-burp : HTTP + Burp Suite 完全正制 (本 Ch02 核心)

このチャプターは **ウェブハッキング全体過程で最も重要な基礎**である。  
クリハクティブ本でも Ch02を相当に詳細に扱っている。

## 学習目標
- HTTP リクエスト/応答の全ての構成要素を正確に理解
- **Burp Suite**で全てのウェブトラフィックを拡え取り、修正し、再送信する根性記憶を作る
- "ユーザー入力値がどうやってサーバまで到達するか"を視覚的に体感
- パラメータ変更の味見本 (本 Ch01 最後の例を再現)

## 0. 事前準備 (Windows)

### Burp Suite Community インストール
1. https://portswigger.net/burp/communitydownload 接続
2. Burp Suite Community Edition ダウンロード + インストール
3. 初めて実行すると CA 認証書インストールするよう出てくる → **必ずインストール** (ブラウザが Burp が中間に入るのを信頼させる為)

### ブラウザプロクシ設定 (強力推奨: FoxyProxy)
- Chromeに **FoxyProxy** 拡張インストール
- 新しいプロクシ追加:
  - Title: Burp
  - Proxy IP: 127.0.0.1
  - Port: 8080
  - Pattern: `*` (または望むドメインだけ)
- 必要なときだけ ON/OFF できるように作る

手動設定も可能だが、毎回設定変えるのが面倒くさいから FoxyProxy 推奨。

## 2. 必ずやってみような実習 (順番に)

### 実習 A: GET リクエスト + パラメータ変更 (本初期例をそのまま)
1. Burpを **Intercept ON** 状態にする
2. メインページで"会員情報を見る"フォーム送信 (user=chulsu)
3. Burpでリクエストが止まる → **Headers, Params タブ**を詳細に見る
   - GET /profile?user=chulsu HTTP/1.1
   - Host, User-Agent, Cookie, Accept などヘッダ観察
4. `user=chulsu` を `user=sumi` に **直接修正** して Forward
5. ブラウザに **水美の電話番号**が出てくるか確認

**成功基準**: 水美の電話番号(010-9876-5432)を自分の目で確認。

### 実習 B: POST リクエストバディを見る
1. ログインフォームで chulsu / test123 送信
2. Burpで **リクエストバディ** 確認 (application/x-www-form-urlencoded)
   - username=chulsu&password=test123
3. Repeaterで送って password 値を何でも変更して何度も試してみよう

### 実習 C: クッキー脱取及びセッションハイジャッキング味見本
1. ログイン成功後 "私の情報を見る" リンククリック
2. Burp Historyで `/myinfo` リクエストを探す → Requestに `Cookie: session_user=chulsu` があるか確認
3. Repeaterでコピー
4. Cookie 値を `session_user=admin` に変更して Go
5. 管理者情報が出てくるか確認

これが正に後で **セッションハイジャッキング**へ発展します (XSS チャプターで本格出現)。

### 実習 D: デバッグページ活用
`/debug/request` ページへ行って現在リクエストの全ての情報を JSONみたいに見れる。  
Burp なしでも大概的な構造把握に便利だが、 **本物の実力は Burpで養う**。

## 3. Burp 核心機能 (このチャプターで集中すること)

| 機能       | どこで使うか                  | 今回の実習でやること                     |
|------------|------------------------------|-----------------------------------------|
| Proxy      | 全てのトラフィック拡え取り         | Intercept ON/OFF, Forward              |
| HTTP History | 過去リクエスト/応答記録       | どのリクエストがいつ行ったか復習            |
| Repeater   | 同じリクエストを複数回変更     | パラメータ/クッキー/ヘッダ心のまま変えてみよう   |
| Decoder    | URL エンコーディング、Base64 など        | 後で payload 作るとき有用             |
| Intruder   | 自動化攻撃 (後で)         | まだはスキップ、SQLi/XSS のとき本格使用     |

## 4. このアプリで発見できる"脆弱なコード"ポイント

`app.py`を開いて次を直接探してみよう:

- `/profile` ラウトの `username = request.args.get("user", ...)` 後直接 DB 取得
- あらゆる権限チェックなし (`現在ログイン中の人がこの user を見る権限があるか?`)
- `/myinfo` でクッキーだけで認証 (署名なし、ただの username)

**本の核心メッセージ**:  
"大半の脆弱点はユーザー入力値に対する検証未少から始まる。"
