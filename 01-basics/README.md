# 01-basics : ウェブハッキングとは？ + なぜウェブか？ (本 Chapter 01)

このチャプターは技術よりも **マインドセット** と **根本原因** を扱う。

## 本で言っている核心ポイント (要約)

1. ウェブハッキング = ウェブアプリケーションに対する攻撃
2. ウェブサービスが攻撃対象 1順位である理由
   - 防火壁を穿って入ってくる必要がほぼない (80/443ポートはほぼ常に開いている)
   - ユーザー入力値を **必ず** 受け取らなければならない構造
   - 入力値検証を正しくしないと直ちに脆弱点
3. 大半の脆弱点は"ユーザー入力値に対する検証未少"から始まる
4. 攻撃技法だけ外もずに、**プログラムがどう動作するか**を理解しないと構造的な脆弱点を見つけられない

## この実習アプリで確認すること

`app.py`を実行して下のようにしてみよう。

### 実習 1: 他人の"非密メモ"を見る
```powershell
cd 01-basics
python app.py
```

ブラウザで:
- `http://127.0.0.1:5000/memo?owner=sumi` 接続
- 水美の非密情報が見えるか？

### 実習 2: 管理者フラグ脱取
- `?owner=admin` で試行
- フラグが見えたら成功 (`フラグ{webhacking_is_fun_with_input_validation}`)

### 実習 3: コードで原因を探す
`app.py` の `view_memo()` 関数を開いて次を確認:

```python
owner = request.args.get("owner", "chulsu")
c.execute("SELECT * FROM memos WHERE owner = ?", (owner,))   # ← ここまではましまし
# しかし "このリクエストを送った人が owner のメモを見る権限があるか？" に対する検査が完全にない
```

**この一行の不在**が脆弱点の開始です。
